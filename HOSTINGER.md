# Hostinger launch

## Google sign-in

Email signup now includes a password and repeat-password validation (15–128 characters). The email verification link requires the chosen password again before setting it; an existing password is never replaced by another signup request. Passwords are salted with scrypt and excluded from audit snapshots and Excel exports. Login supports passwords, Google or a private email link. Without Remember me, the cookie ends with the browser session and its server session expires within eight hours. Remember me uses a 30-day cookie/session. Google follows the same preference. Changes require the included database migration.

The soundtrack is an original 124 BPM melodic-house arrangement generated by Web Audio: chord progression, plucked melody with filtered echo, offbeat bass, drums and a periodic breakdown. It needs no external copyrighted music file. Sound starts after audience interaction and the existing sound switch mutes it.

The Google button uses the official Google icon and Google Sans font, served locally, with Google's dark button colors. [Google's branding guide](https://developers.google.com/identity/branding-guidelines).

Create a Google OAuth client of type **Web application** for this festival. Configure its consent screen with the festival's name and domain and only the `openid email profile` scopes. Register the exact authorized redirect URI `https://www.thosewhoknowtheyknow.com/api/auth/google/callback`. For local development you can separately register `http://localhost:8140/api/auth/google/callback`. Put GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET directly in Hostinger's environment settings, then redeploy. These are separate from Razorpay credentials. Google sign-in is disabled until the client and database are configured; the email-link login remains available. [Google's official OpenID Connect instructions](https://developers.google.com/identity/openid-connect/openid-connect).

The app checks Google's signed ID token, audience, issuer, expiry, verified email and nonce. Browser-bound one-time state and PKCE protect the redirect flow. Google access/ID tokens are not stored; the server issues the same secure session as email login. No Gmail password is collected.

Checkout uses the account's verified email and asks for name/Indian mobile number. These details are stored with each booking and in the reusable customer profile. Admins can search/page through customer details and export all customers in Excel. The `/admin` page and its APIs require an authorized admin account; ordinary visitors have no admin link. The local `/admin-preview` remains a clearly labelled sample demonstration and is not available in production.

Upload `TWKTK-hostinger.zip` using **Websites → Create Website → Web App → Upload your website files**. Use the Node.js web app service, rather than uploading static files into public_html: the server handles ticket payments, authentication and email.

Use Node 24 (22 also supported), the Express or Other framework, project root as the root directory, `npm ci --include=dev` for installation, and `npm run build` for the build command. The front-end output is `dist`, but keep the entire project for the server. Set the server entry file to `hostinger.mjs`. If the panel asks for a start command instead, use `npm run start:hostinger`. Let the platform supply its PORT. The startup migrates PostgreSQL before accepting requests; it does not replace existing prices or inventory.

Hostinger supports Node.js apps on its Business and Cloud plans, with a ZIP upload option. [Official Hostinger setup](https://www.hostinger.com/support/how-to-deploy-a-nodejs-website-in-hostinger/).

In Hostinger's environment variable settings, add the values listed in `.env.example`. Set NODE_ENV=production, APP_URL=https://www.thosewhoknowtheyknow.com, ADMIN_EMAILS=mayank@emergencenetwork.in, and CONTACT_EMAIL=Mayank@emergencenetwork.in. Configure the proxy hop count according to your actual Hostinger deployment; do not guess a broad trust rule. [Hostinger environment settings](https://www.hostinger.com/support/how-to-add-environment-variables-during-node-js-application-deployment/).

This application requires PostgreSQL. Connect a hosted PostgreSQL database with backups using DATABASE_URL. If your Hostinger plan only includes MySQL, use a separate hosted PostgreSQL service or a properly configured PostgreSQL instance on your VPS. Use certificate-verified TLS for an external database: DATABASE_SSL=true. Never upload a local JSON database or client records.

For outgoing email, configure SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS and MAIL_FROM from your provider. If you use **Hostinger Email**, its documented SMTP host is smtp.hostinger.com with SSL port 465; username is your full mailbox address. This app enables implicit TLS on port 465. Titan or another provider may use different settings; copy the exact details from your mailbox panel. Verify SPF, DKIM and DMARC. [Hostinger Email settings](https://support.hostinger.com/en/articles/1575756-how-to-get-email-account-configuration-details-for-hostinger-email).

Replace the secret shared in chat. Enter the live Razorpay key ID and replacement secret directly in the host settings; enter a separate webhook signing secret. Configure the live webhook https://www.thosewhoknowtheyknow.com/api/webhooks/razorpay for payment.captured and order.paid with the matching signing secret. Enable automatic capture. Test keys do not charge real money.

Connect your GoDaddy domain using the exact DNS instructions in your Hostinger panel. Preserve email MX and verification records, confirm HTTPS, and redirect the apex domain to www. Domain ownership is not the same as a deployed application.

After deployment, open `/admin` and sign in as Mayank@emergencenetwork.in. Check the database/email/Razorpay status cards. Confirm each event's venue and start time, then open the desired ticket categories and the gathering. Initial inventory is **200 units per category**, editable individually. Tables count tables for six guests, so 200 tables mean 1,200 admissions. Total event capacity begins at 2,200 admissions (five 200-person categories plus tables); also editable. Seed migrations leave existing dashboard edits unchanged. Mumbai retains its original price list but needs a date and a gathering created before sales can open there.

Run the payment, confirmation email, duplicate-webhook and Excel checks in HOSTING.md. Sales are not live until the hosted database, mailbox, live keys, webhook, HTTPS and event details are configured. The local `/admin-preview` is sample data only and is unavailable in production.
